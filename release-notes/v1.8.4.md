**Faster figure calculation, and no more periodic stutter on moving curves.** The processor work behind every frame is roughly halved on most presets, so the main view runs smoother and the preview grid gets more time to animate. Moving self-similar curves no longer pause every second or so. Nothing looks different: every preset draws the same picture it drew before.

## Faster on every machine

The figure calculation is the largest share of the processor's work in each frame, and on a slower machine
it decides the frame rate. Three changes make it cheaper without changing the picture:

- **Wave figures** compute their shape for all particles at once instead of particle by particle. Measured: 66–73 %
  less processor time per frame on presets such as `Quader`, `Cycloid` and `Aurora Borealis`.
- **Colours** are worked out from a table that changes only when the colour settings do, instead of being
  recalculated for every particle every frame.
- **Self-similar curves** are rebuilt only when something about their shape changes; a still curve reuses its
  points. Measured: 34–54 % less processor time on the curve presets.

## No more stutter on moving curves

A `Customize` curve whose shape keeps moving (for example a breathing Twist, as in **Chaos to Order**) is rebuilt
every frame. It used to create new memory for that each time, and clearing it away caused a short pause every
second or so, which showed as an uneven frame rate. It now reuses the same memory, and the rebuild itself is
cheaper. Measured on Chaos to Order: the figure calculation halved, the frame rate rose from 47 to 72 fps, and the
slowest frames (p95) fell from 25 ms to 17 ms.

To see the figures on your own machine, add `?perf=1` to the address; the user manual's section 4.3, *If it runs
slowly*, explains every line.
